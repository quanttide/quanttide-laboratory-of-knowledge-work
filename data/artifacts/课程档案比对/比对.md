# 比对：个人课程档案 × 课程研发档案

2026-09-10

## 两边

| | work 侧（个人档案） | course 侧（课程研发档案） |
|---|---|---|
| 位置 | `quanttide-work/data/profile/iGuo/course/` | `quanttide-course/data/profile/` |
| 里面 | `index.md`（量潮课堂）、`knowledge-work.md`、`production-internship.md` | `data-engineering/`、`production-internship/lesson1-second-brain/`、`vibe-coding/`（3 课时） |
| 记什么 | 想法与制度：为什么做、边界在哪、怎么算验证成了 | 课程内容：课时 / 场景 / 步骤 / 验收 |
| 形态 | 散文，人看 | 单源双格式：`index.md` 人看 + `index.json` 机器吃；场景 `0X-*.md/.json`；派生 `index.html` |
| 粒度 | 一门课一段 | `<course>/lessonN-<slug>/<scene>` |

## 两边都有的

- **production-internship**：work 侧记制度（指导只针对群体、付费边界是刚性制度）与验证约定（壳是第一份数据、是 baseline、观察不纠正）；course 侧有 `lesson1-second-brain`（`index.md` + `index.json`）。同一门课——一侧答「为什么这么办」，一侧答「课里有什么」，两边**互不引用**。
- 「量潮课堂」的自举与打通（学生作业即 PR、组织隔离、不开发专门课堂功能）只活在 work 侧；它约束的是课程**组织方式**，course 侧没有承接它的位置。

## 缺口

work 侧有、course 侧没有：

- **知识工作**（方法论课）：course 侧只有 `data-engineering`、`production-internship`、`vibe-coding` 三门，没有这门课。
- **验证目标与风险**：验证目标（学生用了之后产出质量是否可见提升）、风险（日志流于形式的激励设计）在 course 侧没有课程级约束字段。
- 组织设想（量潮课堂、组织隔离）无对应。

course 侧有、work 侧没有：

- **vibe-coding**（3 课时）、**data-engineering**（仅 `index.md` 占位）：个人档案没记这两门课，也没有参与角色。
- **格式约定**（单源双格式、课时目录约定、`acceptance{criteria, method, on_fail}`）：个人档案无格式。

## 格式差（最要紧的一条）

course 侧可机读（`index.json` 带 `acceptance.criteria/method/on_fail`），work 侧只有散文——两边的同一件事（比如 production-internship 的验收）**无法自动对账**。work 侧那些验证约定（壳是 baseline、观察不纠正），在 course 侧的 `acceptance` 里看不到。

## 结论

建议（待创始人拍板）：

1. **不并文件，各守一层**：想想法与制度（为什么这么办）留在 work 侧；课程内容（课里有什么）留在 course 侧；两边各加一条互引链接。
2. **work → course**：production-internship 的验证约定（壳是 baseline、观察不纠正、指导只针对群体）该成为课程级约束或课时 `acceptance` 的来源；「知识工作」课要做，先到 course 侧立课。
3. **course → work**：个人档案补 `vibe-coding`、`data-engineering` 的参与记录（含角色），否则个人档案落后于课程档案。
4. **格式对齐**：想自动对账，work 侧的验证约定得落成可机读的 `acceptance`；在那之前只能人比。

闸门：以上四条由创始人定；course 侧属别的仓库，动它要授权。
