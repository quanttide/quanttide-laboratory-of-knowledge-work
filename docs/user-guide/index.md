# 知识工作工具箱

一个程序，八个动作，分四组——工作区看整体，查看看一件，契约与案卷各管一种记录。命令行与窗口两个入口，分组与动作都一样。

| 组 | 动作 |
|----|------|
| 工作区 | 目录、审计 |
| 查看 | 找文档、看材料 |
| 契约 | 写契约骨架、核对契约 |
| 案卷 | 写案卷骨架、核对案卷 |

```bash
./kg <动作> [参数]        # 实验室目录下直接跑
./kg-gui                  # 开窗口版（同一个程序）
uv pip install -e .       # 或装成命令：kg / kg-gui
```

## 找一份文档

```bash
$ kg find 材料
[规格] docs/specification/piece/material.md
$ kg find 材料 --show      # 连同正文一起看
$ kg find journal
[产物] data/journal
[案例] docs/gallery/artifacts/journal.md
```

按名字找，同时认**文件名**和**篇内标题**——因为体系规定文件名用英文、标题用中文，两者不互译。找不到就模糊兜一层（`日志规范` 会落到 `日志`）。

## 看目录

```bash
$ kg catalog                # 按资产种类列出全部条目
$ kg catalog --json 目录.json   # 导出目录（其他程序可读）
```

## 审计

```bash
$ kg audit
审计通过：二十格齐备，无未登记目录。
$ kg audit --json 报告.json   # 落出「结果 / 缺资产 / 未登记」，给别的程序读
```

两个方向一起查：**契约有而仓库没有**（缺资产）、**仓库有而契约没有**（未登记）。后者尤其有用——新目录出现时它会自己冒出来，提示你「这个还没登记」。

## 写一份契约

开工前把要什么写清楚，做完照着核对：

```bash
$ kg new-contract 契约.md      # 写出骨架
$ kg audit-contract 契约.md    # 核对四段，跑机械核对，列出闸门项
  ✓ 目标   ✓ 输出形态   ✓ 必须包含   ✓ 检查项
契约完整。
机械核对：
  ✓ 机械：目标侧文件已就位（path:data/journal/README.md）
  ✓ 机械：旧位置的副本已删除（absent:data/journal/old.md）
闸门项（留给人拍板）：
  - 闸门：落点与源位置同构
```

契约的四段是：**目标**（要什么）、**输出形态**（交付成什么样）、**必须包含**（不能漏的要素）、**检查项**。检查项分两类——能写成断言的**机械核对**（判据写进契约，工具照跑），只能人看的**闸门项**（留给验收拍板）。

判据写在反引号里，共四种，路径一律相对仓库根：

| 判据 | 意思 |
|------|------|
| `` `path:docs/index.md` `` | 该路径存在 |
| `` `absent:docs/old.md` `` | 该路径不存在 |
| `` `contains:docs/index.md=第二大脑` `` | 该文件含这段文字 |
| `` `run:test -f docs/index.md` `` | 该命令在仓库根退出码为零 |

## 看一条材料

材料是还没做成成品的输入，四字段现填——类型取扩展名、内容取正文、来源取上级目录与文件名、时间取**文件自己那个仓库**里首次提交的日期（退回文件名里的日期）。原始与材料之分不占字段，由位置承担：日志是原始，其余是材料。

```bash
$ kg material                         # 没给路径就看日志与档案里的全部文档
材料                                               类型  阶段  时间        来源
data/journal/iGuo/2026-09-10.md                    md    原始  2026-09-10  iGuo/2026-09-10.md
data/profile/iGuo/org.md                           md    材料  2026-09-10  iGuo/org.md
$ kg material data/profile/iGuo/org.md --json 材料.json
```

## 记一次案卷

一件交付做完，把过程记下来：

```bash
$ kg new-dossier 案卷.md       # 写出骨架
$ kg audit-dossier 案卷.md     # 核对四段
  ✓ 生成者产出   ✓ 审查者报告   ✓ 人类裁决   ✓ 最终成果
案卷完整。
```

案卷的价值在过程：谁按什么做的、核对了什么、谁拍的板、最后交出什么。少一段就自查不过。

## 窗口版

不想敲命令就用 `./kg-gui`：左栏选动作，右栏填参数（文件类带「浏览…」），点执行，下边出结果。

- 结果有表格就画表，没有就贴文字——同一个动作在命令行与窗口里是同一套算法，不会两处不一样；
- 表里带路径的行，双击用系统默认程序打开；
- 目录、审计、看材料带「导出…」，落 JSON 给别的程序读；
- 顶部可改工作区（默认从当前目录往上找）；
- 出错留在窗口里显示，不会让界面崩掉。

## 这套工具取舍了什么

**留下的**是动作——七个都能在仓库上直接跑，不需要启动任何服务，也不需要数据库。

**砍掉的**是三样：

- **验证脚本里的样本数据**——样本是用来验证结构的，结构立住之后样本就是负担；
- **一次性验证**（材料字段那条）——结论已经拿到（四字段够用、阶段由位置承担），不需要常驻一个命令；
- **服务端与数据库**——从第一份碎片到最后一个动作，没有一处需要它：文档在文件里，索引现扫现生成；
- **实验里的结构代码**——同一套四段写在两处就是两份事实源；结构归工具，样本留成 Markdown（真实迁移契约、真实案卷，都能被工具当场核对通过）。

**合并方式**：一个包一个入口（`src/kg/`），契约层、目录层、判据、记录各是一处；早先四份碎片与两个命令行壳都并了进来，不复制代码——一份事实源。

## 边界

- **只读仓库，不改内容**——找、看、审计都不动文件；写入仍由人和 AI 在对话里做，提交仍走 git；
- **不是服务**——没有端点、没有数据库、没有后台进程；
- **认名字与位置**——名字（文件名 + 中文标题）管找到，位置（资产与落点规则）管归属；这两样是地基，工具只是把地基用起来。
