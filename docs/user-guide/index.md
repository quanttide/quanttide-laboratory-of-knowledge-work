# 知识工作工具箱

程序的中心是**工作流**——一串标准任务（编排定义）；每次工作就是它的一次**运行**。命令与窗口里的动作，只是把某个标准任务执行一次。

```bash
./kg workflow             # 看工作流：默认「一次交付」的七个标准任务与各自产出物
./kg run --list           # 有哪些运行、各自下一个标准任务
./kg-gui                  # 开窗口：台面就是这次运行
uv pip install -e .       # 或装成命令：kg / kg-gui
```

界面要 PySide6 的窗口模块；缺了就在实验室内建个虚拟环境：`uv venv .venv && uv pip install -e '.[gui]'`，然后 `.venv/bin/kg-gui`。

## 工作流：一次交付

七个标准任务，线性，一件工件往下走：

| 标准任务 | 干什么 | 交出什么 | 怎么算完 |
|---|---|---|---|
| 材料 | 把还没做成成品的输入记进来 | `materials.md` 一行 | 四字段填得出 |
| 指令 | 写下这一次的指令 | `task.md` | 三段齐全：目标 / 步骤 / 验收 |
| 核对 | 按验收跑机械核对 | 报告里的审查者报告 | 机械项有结论，闸门项列给人 |
| 产出 | 把做出来的东西记上 | 报告里的生成者产出 | 落在盘上、路径写得清 |
| 裁决 | 谁拍板、决定是什么 | 报告里的人类裁决 | 有人、有决定 |
| 成果 | 把产出收束成成果 | 报告里的最终成果 | 成果由产出收束而来 |
| 历史 | 写下这一次的来龙去脉 | 历史 | 叙事，人写 |

`kg workflow` 把这张表打印出来。

## 一次运行怎么走

```bash
$ kg run --new 数据归仓 --about "所有数据放实验室 data/，禁止过滤"
起了：…/examples/default/data/runs/数据归仓
下一步：材料——记一条材料（还没做成成品的输入）

$ kg run 数据归仓 --material AGENTS.md              # 材料：四字段现填
$ kg run 数据归仓 --instruction                    # 指令：写出骨架，步骤与验收你填
$ kg run 数据归仓 --review                         # 核对：跑验收里的机械判据，写进报告
$ kg run 数据归仓 --output examples/default/AGENTS.md
$ kg run 数据归仓 --decision "创始人：数据全部放实验室 data/。"
$ kg run 数据归仓 --finish                         # 成果：产出收束
$ kg run 数据归仓 --history "先有报告/历史的归位，再有数据只在本仓的纪律。"

$ kg run 数据归仓
  ✓ 材料 ✓ 指令 ✓ 核对 ✓ 产出 ✓ 裁决 ✓ 成果 ✓ 历史
七个标准任务都做过了；报告与历史都在该在的格子里
报告：data/report/数据归仓.md　历史：data/history/数据归仓.md
```

**报告不是手填的**：审查者报告由指令的机械核对跑出，最终成果由产出收束，流水是你每一步的痕迹。历史与裁决要人写——机器替不了。

**指令也不是程序替你写的**：`--instruction` 只写出骨架（目标已填），程序随后把 `task.md` 打开，你补步骤与验收；三段齐全这一步才算完成。

## 一次运行在盘上长什么样

**所有数据放本仓 `data/`**（工作纪律，见 `AGENTS.md`），程序默认就写在这儿，`--data` 可换：

```text
data/runs/数据归仓/        现场：task.md（指令三段）、materials.md、log.jsonl
data/report/数据归仓.md    事件：生成者产出 / 审查者报告 / 人类裁决 / 最终成果
data/history/数据归仓.md   叙事：这一次的来龙去脉
data/samples/             判例：真实指令与真实报告
```

都是 Markdown 与一行行 JSON，能读能改也能进版本库。

## 窗口

`./kg-gui` 两页：

- **台面**（默认）——上方选一次运行、可以新建；中间七个标准任务的状态；点「下一步」执行它，也能点任意一个补做；下方是流水。要填的会先问：材料与产出让你选文件，裁决与历史让你写句话；点「指令」后程序会打开 task.md 让你补齐三段。
- **浏览**——工作区层面的动作：目录、审计、找文档、看材料，以及不挂在运行上的一件件记录（写指令骨架、核对指令、写报告骨架、核对报告）。

顶栏可改工作区（默认从当前目录往上找），也显示数据落点。

## 浏览页的几个动作

```bash
$ kg catalog                    # 目录：按资产种类列出全部条目
$ kg audit                      # 审计：资产表有而工作区无、工作区有而资产表无
$ kg audit --make               # 缺的格子当场补建（独立仓库那三格不凭空建）
$ kg find 材料 --show           # 按名找：认文件名与中文标题，找不到模糊兜一层
$ kg material                   # 看材料：日志与档案里的文档，四字段现填
```

指令的判据写在「验收」段里，四种，路径相对工作区根（写绝对路径则按绝对路径，跨仓库核对用）：

| 判据 | 意思 |
|------|------|
| `` `path:docs/index.md` `` | 该路径存在 |
| `` `absent:docs/old.md` `` | 该路径不存在 |
| `` `contains:docs/index.md=第二大脑` `` | 该文件含这段文字 |
| `` `run:test -f docs/index.md` `` | 该命令在工作区根退出码为零 |

没有判据的条目是**闸门项**，原样列给人拍板。

## 这套工具取舍了什么

**留下的**是动作——都能在工作区上直接跑，不需要启动任何服务，也不需要数据库。

**砍掉的**：

- **验证脚本里的样本数据**——样本立完结构就是负担；
- **一次性验证**（材料字段那条）——结论已经拿到（四字段够用、阶段由位置承担）；
- **服务端与数据库**——文档在文件里，索引现扫现生成；
- **实验里的结构代码与「案卷」这个词**——结构归程序，样本留成 Markdown；事件归报告、叙事归历史。

**合并方式**：一个包一个入口（`src/kg/`），资产层、目录层、判据、记录、工作流各是一处；命令行与窗口共用同一层算法（`report.py`），不复制。

## 边界

- **不改工作区**——除非你点了明确要写的动作（起运行、记材料、写审查报告、补建格子、导出）；
- **不是服务**——没有端点、没有数据库、没有后台进程；
- **认名字与位置**——名字（文件名 + 中文标题）管找到，位置（资产与落点规则）管归属；
- **数据只在本仓**——所有数据放 `data/`，不写到实验室外（工作纪律）。
