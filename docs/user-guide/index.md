# 知识工作工具箱

程序的中心是**工作流**——串联的工作步骤（编排定义）；**任务**是它的一次执行实例。命令与窗口里的动作，就是走某一步。

```bash
./kg workflow --list      # 有哪些工作流（串了哪些步骤）
./kg task --list          # 有哪些任务（工作流的一次执行）、各自下一步
./kg-gui                  # 开窗口：台面就是当前这件任务
uv pip install -e .       # 或装成命令：kg / kg-gui
```

界面要 PySide6 的窗口模块；缺了就在实验室内建个虚拟环境：`uv venv .venv && uv pip install -e '.[gui]'`，然后 `.venv/bin/kg-gui`。

走一遍看这里：[过程](process.md)——先串步骤、再执行，拿课程档案比对那次真事说话（写工作流可改、起任务复用、走一步、看、收尾）。

## 工作流：串联的步骤（定义）

```bash
$ kg workflow --new 课程档案比对 --steps 定位,比对,结论 --note "比对两边的档案"
写下工作流：…/data/workflows/课程档案比对.md
$ kg workflow 课程档案比对
  定位：1 条判据  比对：3 条判据  结论：1 条判据
```

工作流是数据不是代码，写在 `data/workflows/<名字>.md` —— 步骤用 `### 步骤名` 串起来，每步自带验收（机械的当场判，闸门的留给人）：

```markdown
### 比对

- 做什么：把两边逐项比一遍
- [ ] 机械：产物落成 `path:examples/default/data/artifacts/report/比对.md`
- [ ] 闸门：创始人点头
```

## 任务：工作流的一次执行（实例）

```bash
$ kg task --new 课程档案比对 --workflow 课程档案比对 --about "比对 work 侧与课程研发档案"
起了：…/data/tasks/课程档案比对.md

$ kg task 课程档案比对 --done 比对 --note "口径 / 重叠 / 缺口 / 格式差"
✓ 比对：口径 / 重叠 / 缺口 / 格式差
  ✓ 机械：产物落成（path:…/比对.md）
  ⧗ 闸门：创始人点头（留给闸门）
下一步：结论

$ kg task 课程档案比对                     # 步骤状态与流水
$ kg task --list                          # 有哪些任务
$ kg task 课程档案比对 --history "先找齐两边，再按四条比……"
```

**同一件任务 = 同一个工作流的一次执行**；跑第二遍就是另一件任务。走一步记一笔，报告机器写，历史人写。

## 数据：三家分放

**所有数据放本仓 `data/`**（工作纪律，见 `AGENTS.md`），`--data` 可换：

```text
data/workflows/<工作流>.md     定义：串联的步骤与判据
data/tasks/<任务>.md           实例：跑哪条工作流、要什么
data/artifacts/report/<任务>.md   报告（事件）
data/artifacts/history/<任务>.md  历史（叙事）
data/artifacts/log/<任务>.jsonl   流水
```

## 窗口

`./kg-gui` 两页：

- **台面**（默认）——上方选一次运行、可以新建（顺手填步骤清单）；中间是步骤表（步骤 / 关联的任务 / 状态），双击行打开那个任务，下面填一句「这一步做了什么」，点「执行这一步」；再下面是流水。「写历史…」让你记下这一次的来龙去脉。
- **浏览**——工作区层面的动作：目录、审计、找文档、看材料，以及不挂在运行上的一件件记录（写指令骨架、核对指令、写报告骨架、核对报告）。

顶栏可改工作区（默认从当前目录往上找），也显示数据落点。

## 浏览页：工作区层面的动作

```bash
$ kg catalog                    # 目录：按资产种类列出全部条目
$ kg audit                      # 审计：资产表有而工作区无、工作区有而资产表无
$ kg audit --make               # 缺的格子当场补建（独立仓库那三格不凭空建）
$ kg find 材料 --show           # 按名找：认文件名与中文标题，找不到模糊兜一层
$ kg material                   # 看材料：日志与档案里的文档，四字段现填
```

指令的判据写在「验收」段里，四种，路径相对工作区根（写绝对路径则按绝对路径，跨仓库核对用）：

| 判据 | 意思 |
|------|------|
| `` `path:docs/index.md` `` | 该路径存在 |
| `` `absent:docs/old.md` `` | 该路径不存在 |
| `` `contains:docs/index.md=第二大脑` `` | 该文件含这段文字 |
| `` `run:test -f docs/index.md` `` | 该命令在工作区根退出码为零 |

没有判据的条目是**闸门项**，原样列给人拍板。

## 这套工具取舍了什么

**留下的**是动作——都能在工作区上直接跑，不需要启动任何服务，也不需要数据库。

**砍掉的**：

- **验证脚本里的样本数据**——样本立完结构就是负担；
- **一次性验证**（材料字段那条）——结论已经拿到（四字段够用、阶段由位置承担）；
- **服务端与数据库**——文档在文件里，索引现扫现生成；
- **实验里的结构代码与「案卷」这个词**——结构归程序，样本留成 Markdown；事件归报告、叙事归历史。

**合并方式**：一个包一个入口（`src/kg/`），资产层、目录层、判据、记录、工作流各是一处；命令行与窗口共用同一层算法（`report.py`），不复制。

## 边界

- **不改工作区**——除非你点了明确要写的动作（起运行、记材料、写审查报告、补建格子、导出）；
- **不是服务**——没有端点、没有数据库、没有后台进程；
- **认名字与位置**——名字（文件名 + 中文标题）管找到，位置（资产与落点规则）管归属；
- **数据只在本仓**——所有数据放 `data/`，不写到实验室外（工作纪律）。
