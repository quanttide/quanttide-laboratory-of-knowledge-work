# 知识工作工具箱

程序的中心是**任务**：它从材料走到成果，中途发生的事都记进它的流水，记录按资产进格——**报告（事件）进 `data/report/`，历史（叙事）进 `data/history/`**。命令与窗口里的动作，只是它的下一步。

```bash
./kg task --list          # 有哪些事、各自下一步
./kg-gui                  # 开窗口：主界面就是当前这个任务
uv pip install -e .       # 或装成命令：kg / kg-gui
```

界面要 PySide6 的窗口模块；缺了就在实验室内建个虚拟环境：`uv venv .venv && uv pip install -e ".[gui]"`，然后 `.venv/bin/kg-gui`。

## 任务怎么走

七格状态，一步一格，程序只摆出该做的那一步：

```
材料 → 契约 → 核对 → 产出 → 裁决 → 成果 → 历史
```

前三格是输入与约定，中间三格是事件（进报告），最后一格是叙事（进历史）。

```bash
$ kg task --new 工具成形 --about "把动作串成一件在走的活"
起了：/home/iguo/repos/quanttide/domains/quanttide-work/examples/default/data/tasks/工具成形
下一步：材料——记一条材料（还没做成成品的输入）

$ kg task 工具成形 --material data/journal/iGuo/2026-09-10.md
记下材料：data/journal/iGuo/2026-09-10.md          # 四字段现填
$ kg task 工具成形 --contract                       # 以记下的材料立契约
$ kg task 工具成形 --review                         # 跑机械核对，审查者报告写进案卷
$ kg task 工具成形 --output examples/default/src/kg/task.py
$ kg task 工具成形 --decision "创始人 2026-09-10 通过"
$ kg task 工具成形 --finish                         # 产出收束成成果，写进报告
$ kg task 工具成形 --history "先接接口不够，主界面得是这个任务。"   # 历史：叙事，人写

$ kg task 工具成形
  ✓ 材料  ✓ 契约  ✓ 核对  ✓ 产出  ✓ 裁决  ✓ 成果  ✓ 历史
七格齐了；报告与历史都在该在的格子里
报告：data/report/工具成形.md　历史：data/history/工具成形.md
流水（最近五条）：
  2026-09-10 20:55　契约　以 data/journal/iGuo/2026-09-10.md 为题
  2026-09-10 20:55　核对　机械核对 3 项
  …
```

**报告不是手填的**：审查者报告由契约的机械核对跑出来，最终成果由记下的产出收束，流水是你每一步的痕迹。历史要人写——叙事机器替不了。

## 任务在盘上长什么样

**所有数据放本仓 `data/`**（工作纪律，见 `AGENTS.md`），程序默认就写在这儿，`--data` 可换：

```text
data/tasks/工具成形/      任务在飞的：task.md / materials.md / contract.md / log.jsonl
├── task.md        这个任务叫什么、要什么
├── materials.md   记进来的输入（类型 / 阶段 / 时间 / 来源 + 时间）
├── contract.md    约定要什么、怎么验收
└── log.jsonl      流水：什么时候、做了什么、结果如何

data/report/工具成形.md   报告（事件）：生成者产出 / 审查者报告 / 人类裁决 / 最终成果
data/history/工具成形.md  历史（叙事）：这个任务的来龙去脉
data/samples/             判例：真实契约与真实报告
```

都是 Markdown 与一行行 JSON，能读能改也能进版本库。程序默认把数据写在本仓 `data/`（`--data` 换数据仓，`--cases` 单独换任务目录）。

## 窗口

`./kg-gui` 两页：

- **台面**（默认）——上方选任务、可以新建；中间七格状态；点「下一步」往前走，也能点任意一步补做；下方是流水。要填的几步会先问：材料与产出让你选文件，裁决与历史让你写句话。
- **浏览**——工作区层面的动作：目录、审计、找文档、看材料，以及不挂在任务上的一件件记录（写契约骨架、核对契约、写报告骨架、核对报告）。表里带路径的行双击用系统默认程序打开；目录 / 审计 / 看材料可「导出…」；选中一行还能「以选中项立契约」。

顶栏可改工作区，默认从当前目录往上找（含 `data/journal` 的目录）。

## 浏览页的几个动作

```bash
$ kg catalog                    # 目录：按资产种类列出全部条目
$ kg audit                      # 审计：契约有而工作区无、工作区有而契约无
$ kg audit --make               # 缺的格子当场补建（独立仓库那三格不凭空建）
$ kg find 材料 --show           # 按名找：认文件名与中文标题，找不到模糊兜一层
$ kg material                   # 看材料：日志与档案里的文档，四字段现填
```

契约的判据写在文件里，四种，路径相对工作区根（写绝对路径则按绝对路径，跨仓库核对用）：

| 判据 | 意思 |
|------|------|
| `` `path:docs/index.md` `` | 该路径存在 |
| `` `absent:docs/old.md` `` | 该路径不存在 |
| `` `contains:docs/index.md=第二大脑` `` | 该文件含这段文字 |
| `` `run:test -f docs/index.md` `` | 该命令在工作区根退出码为零 |

没有判据的条目是**闸门项**，原样列给人拍板。

## 这套工具取舍了什么

**留下的**是动作——都能在工作区上直接跑，不需要启动任何服务，也不需要数据库。

**砍掉的**是三样：

- **验证脚本里的样本数据**——样本是用来验证结构的，结构立住之后就是负担；
- **一次性验证**（材料字段那条）——结论已经拿到（四字段够用、阶段由位置承担）；
- **服务端与数据库**——文档在文件里，索引现扫现生成；
- **实验里的结构代码**——同一套四段写在两处就是两份事实源；结构归程序，样本留成 Markdown（真实迁移契约、真实案卷，都能被程序当场核对通过）。

**合并方式**：一个包一个入口（`src/kg/`），契约层、目录层、判据、记录、任务各是一处；命令行与窗口共用同一层算法（`report.py`），不复制。

## 边界

- **不改工作区**——除非你点了明确要写的动作（开工、记材料、立契约、写审查报告、补建格子、导出）；其余只读；
- **不是服务**——没有端点、没有数据库、没有后台进程；
- **认名字与位置**——名字（文件名 + 中文标题）管找到，位置（资产与落点规则）管归属；
- **数据只在本仓**——所有数据放 `data/`，不写到实验室外（工作纪律）；往外搬要你发话。
