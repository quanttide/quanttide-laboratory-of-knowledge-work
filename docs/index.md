# Default 模块：知识工作技术设计

两种工作模式的技术设计。底座是仓库里的 Markdown 与目录，不引入服务端与数据库。

## 两种模式

**Default（默认入口）**：想不到放哪就放这。人零门槛写下想法，AI 后续按需加工，够用就走。

**Work（指令约束）**：任务有明确交付要求时，先把指令写全再开工——目标、步骤、验收（判据机械的跑、判断的留闸门）；AI 照指令干活，人只拍板。

## 四种记录，各有归处

**材料**：还没做成成品的输入——类型、内容、来源、时间，落在它所在的那一格。

**指令**：这个任务要什么、怎么走、怎么算合格——目标、步骤、验收；判据（机械 / 闸门）住在验收里，就是 `specification/process/task.md` 说的那份指令。

**报告**（侧重事件）：生成者产出、审查者报告、人类裁决、最终成果，落在 `data/report/`。机器可生成——审查者报告由指令的机械核对跑出，最终成果由产出收束。

**日志**（侧重叙事）：这次工作的来龙去脉，落在 `artifacts/journal/`，由人写。

## 工作流与任务

**工作流**是过程的编排定义——一串步骤，用 YAML 存（字段与取值由 schema 定死，意义固定）；每步写着谁做（`executor: agent|human`）与谁判（判据的 `executor: rule|agent|human`）（`specification/process/workflow.md`）。
**任务**是干活的单位：目标 / 步骤 / 验收（`specification/process/task.md`）。

程序**不预置编排**：一次运行的工作流写在自己的现场里，步骤关联哪些任务由现场说了算。

```text
data/
├── workflows/<运行>.md          工作流：步骤清单（- 步骤 → tasks/<运行>/步骤.md）
├── tasks/<运行>/<步骤>.md        任务：目标 / 步骤 / 验收
└── artifacts/<运行>/
    ├── log（流水）            记在任务文件里
    ├── report.md              报告（事件）：执行记录 + 闸门项
    └── history.md             历史（叙事）
```

目录按领域模型分三家：`workflows`（过程·定义侧）、`tasks`（过程·执行侧）、`artifacts`（产物）。

**人执行的是任务**：把某一步关联的任务做一次，这一步就算走完；事实记进流水与报告。做一步就记一笔，不累积别的。

## 三个角色

生成者按指令产出；审查者按验收里的判据核对，机械核对可自动化、判断留给闸门；闸门由人拍板，裁决记入报告。

## 索引与存储

记录都落成仓库里的 Markdown，按资产进对应目录；检索不靠服务，靠目录层扫描生成的名字索引——资产层（`src/kg/assets.py`）与目录层（`src/kg/catalog.py`）。

## 落地顺序

1. 指令结构化：目标、步骤、验收（判据住验收里）。
2. 报告字段化（事件）：生成者产出、审查者报告、人类裁决、最终成果。
3. 材料字段确认：类型、内容、来源、时间。
