# Default 模块：知识工作技术设计

两种工作模式的技术设计。底座是仓库里的 Markdown 与目录，不引入服务端与数据库。

## 两种模式

**Default（默认入口）**：想不到放哪就放这。人零门槛写下想法，AI 后续按需加工，够用就走。

**Work（契约约束）**：一件事有明确交付要求时，先立契约再开工——约定目标、输出形态、必须包含的要素、怎么算合格；AI 按契约干活，人只拍板。

## 三种记录

**材料**：还没做成成品的输入——类型、内容、来源、时间。

**契约**：约定要什么、怎么验收——目标、输出形态、必须包含的要素、检查项。

**案卷**：一件交付的完整过程——生成者产出、审查者报告、人类裁决、最终成果。

## 三个角色

生成者按契约产出；审查者按检查项核对，机械核对可自动化、判断留给闸门；闸门由人拍板，裁决记入案卷。

## 索引与存储

三种记录都落成仓库里的 Markdown，按资产进对应目录；检索不靠服务，靠目录层扫描生成的名字索引——契约层（`src/kg/assets.py`）与目录层（`src/kg/catalog.py`）。

## 落地顺序

1. 契约结构化：目标、输出形态、必须包含的要素、检查项。
2. 案卷字段化：生成者产出、审查者报告、人类裁决、最终成果。
3. 材料字段确认：类型、内容、来源、时间。
