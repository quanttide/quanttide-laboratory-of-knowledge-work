# Default 模块：知识工作技术设计

两种工作模式的技术设计。底座是仓库里的 Markdown 与目录，不引入服务端与数据库。

## 两种模式

**Default（默认入口）**：想不到放哪就放这。人零门槛写下想法，AI 后续按需加工，够用就走。

**Work（契约约束）**：任务有明确交付要求时，先立契约再开工——约定目标、输出形态、必须包含的要素、怎么算合格；AI 按契约干活，人只拍板。

## 四种记录，各有归处

**材料**：还没做成成品的输入——类型、内容、来源、时间，落在它所在的那一格。

**契约**：约定要什么、怎么验收——目标、输出形态、必须包含的要素、检查项。

**报告**（侧重事件）：生成者产出、审查者报告、人类裁决、最终成果，落在 `data/report/`。机器可生成——审查者报告由契约的机械核对跑出，最终成果由产出收束。

**历史**（侧重叙事）：这个任务的来龙去脉，落在 `data/history/`，由人写。

## 任务

三种记录不是三张表，是任务的三个阶段。任务就是 `specification/process/task.md` 说的那次执行实例，落在 `tasks/<名字>/`：

```text
tasks/<名字>/        在飞的：task.md、materials.md、contract.md、log.jsonl
data/report/<名字>.md   事件：四段由动作写出来
data/history/<名字>.md  叙事：人来写
```

七格状态由文件里的事实读出来：材料 → 契约 → 核对 → 产出 → 裁决 → 成果 → 历史。程序只摆出该做的那一步（`src/kg/task.py`），每步的结果自动回到这个任务里——报告不必手填，历史机器替不了。人只出现在两处：写下要什么，与叙事、拍板。

在飞的那部分放哪还没有定论：程序默认 `<数据仓>/tasks/`；报告与历史已经各进既有资产格。

## 三个角色

生成者按契约产出；审查者按检查项核对，机械核对可自动化、判断留给闸门；闸门由人拍板，裁决记入案卷。

## 索引与存储

三种记录都落成仓库里的 Markdown，按资产进对应目录；检索不靠服务，靠目录层扫描生成的名字索引——契约层（`src/kg/assets.py`）与目录层（`src/kg/catalog.py`）。

## 落地顺序

1. 契约结构化：目标、输出形态、必须包含的要素、检查项。
2. 案卷字段化：生成者产出、审查者报告、人类裁决、最终成果。
3. 材料字段确认：类型、内容、来源、时间。
