# 开发计划

v2 怎么长起来：沿 v1 的纪律，按里程碑推进，动手前把决策定下。模型与行为差的说明见[设计](../index.md)。

## 纪律（沿 v1）

数据全落本 app `data/`，不写实验室外；一个包一个入口；库不打印、不找路径，打印与定位归入口层；扫描禁过滤（只跳版本库与构建产物）；不改工作区，除非点了明确要写的动作。

## 里程碑

- **M0 脚手架**：app 目录、`pyproject.toml`（装上即命令）、自带测试骨架（不依赖 pytest，沿 v1）；
- **M1 模型层**：工作流与工作步骤（严格 schema：不认识的字段报错；步骤 `id` 全局唯一、永不重发）、工单（查填、撞名即拒、有账不销）、工作记录（追加幂等、`seq` 自 1 递增不跳号、`step_id` 查填、时间倒序即拒）；工作区身份（`workspace.yaml`：`id` / `name` / `title` / `description` / `created_at` / `updated_at`，缺则首跑生成）；
- **M2 动作层**：命令行对表全部动作（见[功能对表](../user-guide/index.md)）；每个动作在规格端点表里有主——方法、路径、约束逐一核对（无状态、幂等键、撞名即拒、不设 PUT / DELETE）；
- **M3 事件**：`WorkflowCreated`、`WorkOrderCreated`、`WorkRecorded` 落 JSONL；负载按规格——工单事件带工单 `id` 与 `name`、工作区 `id`、`workflow_id` 及声明全文，记录事件带工单名、记录 `id` 与 `seq`、`step_id` 及记录全文；下游按 `id` 幂等去重；
- **M4 材料与产物**：`material` 四字段收录；日志叙事（`order journal`）；产物落点由工作区按名字算（如 `artifacts/<类别>/<工单名>.md`，算法实验室自定）；工作区级动作（`catalog` / `audit` / `find`）按 v1 原样保留；
- **M5 毕业**：对表全绿、测试守着、真事跑一遍（沿用 v1 的毕业条件）。

现状：M0–M4 已落地；M5 毕业未做。实验室不做窗口——v1 的 `kg-gui` 不移植（计划与代码已撤）。

## 决策点

### 一、HTTP 端点壳做不做

背景：规格给每个资源写了 REST 端点与命令行端点，实验室又有「无服务端」原则。

选项：首版做一层 HTTP 薄壳；或不做，只按端点表核对动作语义。

影响：做壳要起服务、引依赖，与「文档在文件里、索引现扫现生成」的路线相悖；不做则动作层与规格端点靠人工对表。

建议：首版不做——动作层与规格端点语义一一对应（方法、路径、约束当对表清单用），HTTP 薄壳留到 M5 之后按需加。

### 二、程序名

背景：v1 叫 `kg`；v2 是重写，版本已由 app 目录区分。

选项：沿 `kg`；或另起一名。

影响：沿旧名省去改脚本与肌肉记忆，但两版同名并存时易混；另起名区分清楚，代价是重记一套命令。

建议：命名归用户，动手前定。

### 三、工单的导出 / 导入

背景：v1 的工作流支持 `--export` / `--import`；规格未给工单规定导出 / 导入。

选项：给工单也做导出 / 导入；或不做。

影响：做则超出规格（实验室自留），且工单内嵌流水、跨区搬运的语义未定；不做则与规格一致。

建议：默认不做。

### 四、定义要不要在文件里带凭证

背景：规格要求工作流与工作步骤各带一枚全局 `id`（UUID，定义侧生成、永不重发）。对 CLI 来说，单工作区里名字本就唯一，手写或迁移一份定义却要凭空编 UUID——v1 的现成定义（如 `data/profile/iGuo/workflows/` 那两份）因缺 `id` 读不进来。

选项：一是**补证**——`id` 可省，程序在写动作时补上并落盘；二是**派生**——文件里不写，读时按「工作区 id + 名字」现算（uuid5，命名空间钉死）；三是**只认名字**——定义、工单、记录一律以名字指认，跨边界带工作区 `id` 与名字。

影响：补证改动最小，但程序会往人写的定义里添字，且落盘后还是带 UUID；派生让文件永不带凭证、定义指哪跑哪，代价是名字一改凭证就变（规格本就禁止改已引用的名字，所以这条落在纪律之内），且派生算法得写进规格，各平台才算得到一块儿；只认名字最省，但与规格「跨边界认 `id`，不靠名字猜」相背，影响最大。

建议：取**派生**。它同时满足「人写的文件不带凭证」与「跨边界仍是 UUID」，也把「名字」与「凭证」这两处本是一件事的事实收敛成一处（合单一事实源）。规矩：**人写的定义不带凭证，程序写的账本（工单、工作记录）照旧带**——账本是事实的实例，不是有名字的定义。规格 `workflow.md` 与 `work-step.md` 的 `id` 字段行需随之改（改为「由工作区按名派生，不入文件」），这步等规格先动。
