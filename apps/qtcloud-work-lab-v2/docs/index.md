# qtcloud-work-lab-v2：按规格重写

实验室 v2 按规格重写，功能对表 v1。规格是准绳（`docs/specification/process/` 的工作流、工作步骤、工单、工作记录四篇），v1 是功能基线（`apps/qtcloud-work-lab-v1`，`kg` 全部动作加窗口）。先对表，再动工。

## 对表原则

- 模型以规格为准：工作流与工作步骤（定义侧）、工单与工作记录（执行侧），封面落笔即封、流水只增不改；
- 功能以 v1 为基线：v1 的每个动作在 v2 都要有归属——沿用、收编或明说退役；
- 规格没规定的操作不发明：v1 里规格之外的动作用「实验室自留」标记，不冒充规格。

## 领域模型

定义侧是工作流与工作步骤：工作流是一串有序的站，每站一枚全局 `id`、一个站名、一句指令；定义一经工单引用即冻结——改站名、删站、调次序，须另立新工作流。

执行侧是工单与工作记录：工单是一张封面落笔即封、内页只进不出的账本，封面写着走哪条工作流，内页是流水；工作记录是账上一笔。进度与完结不落字段、不发完结事件，由流水对照定义推导。

两侧都归属于工作区。位置不进模型：工件与工单落在哪由平台装载时决定，模型只装内容。

## 与 v1 的行为差

1. **任务改叫工单，封面落笔即封**：`workflow_id`、`description` 起单后不可改——改任务、换行程，另开工单，旧单留档；流水为空可删，有账不销。v1「中途改工作流等于改了正在跑的任务的规矩」由定义冻结根治。
2. **位置不进模型**：删去 v1 任务文件里的 `root` / `data` / `workflows` 三个运行上下文字段；工作区根与目录由程序装载时决定（`--root` 等启动参数），工单文件只装内容。
3. **定义一经引用即冻结**：被工单引用的工作流不可改——改步骤、删步骤、调次序，另立新工作流；未被引用的可随意改（直接改 YAML，程序不设改口）；写动作撞上已引用的定义即拒。
4. **流水字段化**：`log`（`at` / `step` / `detail` / `ok`）改为工作记录（`id` / `seq` / `created_at` / `order_id` / `step_id` / `description` / `is_succeeded`），只增不改；改结论的唯一方式是追加一条新记录，「以最新一条为准」只是推导规则。
5. **占位删除**：判据里不再有 `{{report}}` 一类占位——判据路径直接写落点，落点由工作区按名字算（算法实验室自定，规格只说基准由平台给出）。
6. **无完结事件**：走完没走完由流水对照定义推导，不落字段、不发事件；输出末尾照旧印进度与下一步——那是推导结论，不是状态字段。
7. **闸门归定义侧**：闸门即工作流定义里 `human` 判据的所在站，不落封面字段——待拍板清单由定义加流水推导，放行落一条工作记录。v1「走一步累着写」退役：中途冒出来的拍板，人记录的 `description` 承载，或另立定义。
